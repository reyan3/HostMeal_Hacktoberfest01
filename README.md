# HostMeal

Smart meal ideas for hostel life. Tell HostMeal what is in your room, your budget, your cooking time and your equipment, and it suggests meals you can actually make. It also shows which ingredients you are **missing** and lets you collect them into a shopping list.

The meals are generated by a **Gemma** language model hosted on Hugging Face, called through a small **Express** server. The interface is built with **React** and **Tailwind CSS**.

## Features

- **Ingredient chips:** type an item and press Enter or comma, or pick from a grouped list of common items.
- **Many dropdowns:** meal type, diet, budget, cooking time, servings, goal, equipment, taste and pantry basics.
- **Missing ingredients:** every meal shows what you have, what you lack, and a count such as "You have 4 of 6 ingredients".
- **Pantry basics:** salt, oil and common masalas can be counted as already owned, so they do not show up as missing.
- **Shopping list:** add missing items with one tap and copy the list.
- **Sort and filter:** closest match, cheapest, quickest or most protein, and filter by how many ingredients are missing.
- **Recipe view:** expandable ingredients and method for each meal.
- **Loading skeleton:** placeholder cards while the model is working.
- **Responsive layout:** tuned for phones, tablets and desktop (see [Responsive design](#responsive-design)).
- **Optional recipe video card:** if a meal in the API response includes a `youtube` object, the frontend shows a video card for it.

## Architecture

```
┌──────────────────────┐    POST /api/meals    ┌──────────────────────┐
│  Client              │  ───────────────────► │  Server              │
│  React + Tailwind    │                       │  Express             │
│  (Vite, port 5173)   │  ◄─────────────────── │  (port 5000)         │
└──────────────────────┘     { meals: [...] }  └──────────┬───────────┘
                                                          │ chat completions
                                                          ▼
                                               ┌──────────────────────┐
                                               │  Hugging Face        │
                                               │  Inference Providers │
                                               │  (Gemma model)       │
                                               └──────────────────────┘
```

1. The client sends the user's ingredients and preferences to the server.
2. The server builds a prompt and calls the Gemma model on Hugging Face.
3. The server extracts the JSON from the reply, cleans it, drops meals that break the budget or time limit, and retries once if nothing valid comes back.
4. The client works out the missing ingredients by comparing each meal's ingredients with what the user has, then sorts and filters the results.

## Getting started

### Prerequisites

- Node.js 18 or newer (20 or newer is recommended for Vite)
- A Hugging Face account and an access token

### 1. Get a Hugging Face token

1. Sign in at [huggingface.co](https://huggingface.co) and open **Settings → Access Tokens**.
2. Create a token with permission to make calls to **Inference Providers**.
3. Open the model page for the Gemma model you use and accept its license if it asks you to.

### 2. Clone and install

```bash
git clone https://github.com/reyan3/HostMeal_Hacktoberfest01.git
cd HostMeal

# backend
cd server
npm install

# frontend
cd ../client
npm install
```

### 3. Configure environment variables

**`server/.env`**

```env
HF_TOKEN=your_hugging_face_token
PORT=5000
```

**`client/.env`** (optional)

```env
VITE_API_URL=http://localhost:5000
```

The server needs `HF_TOKEN`. `PORT` is optional and defaults to 5000.

The frontend reads its API address from `API_URL` near the top of `client/src/App.jsx`. To use the `.env` value instead, change that line to:

```js
const API_URL = import.meta.env.VITE_API_URL ?? "http://localhost:5000";
```

### 4. Run the app

Use two terminals.

```bash
# Terminal 1: backend
cd server
node server.js
```

```bash
# Terminal 2: frontend
cd client
npm run dev
```

Open the address Vite prints, usually `http://localhost:5173`.

The server uses ES module imports, so `server/package.json` must contain `"type": "module"`.

### Testing on a phone or tablet

`localhost` on a phone or tablet points at the device itself. Start Vite with `npm run dev -- --host`, open the network address it prints, and set `API_URL` to your computer's local IP, for example `http://192.168.1.20:5000`.

To check layouts without a device, open your browser's dev tools, turn on the device toolbar and try a phone preset, an iPad preset (768px to 820px wide in portrait) and a desktop width. Rotate the device to see the landscape layout too.

## API

### `POST /api/meals`

Request body:

```json
{
  "ingredients": ["rice", "eggs", "onion", "tomato"],
  "budget": 80,
  "time": 20,
  "servings": 1,
  "goal": "High protein",
  "equipment": "Gas stove",
  "diet": "Eggetarian",
  "mealType": "Any meal",
  "taste": "Spicy"
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `ingredients` | string[] | Required, at least one item |
| `budget` | number | Maximum cost in ₹ |
| `time` | number | Maximum cooking time in minutes |
| `servings` | number | Defaults to 1 |
| `goal` | string | For example Normal, High protein, Low cost, Healthy, Filling |
| `equipment` | string | For example Gas stove, Microwave, No equipment |
| `diet` | string | Vegetarian, Eggetarian, Non-vegetarian or Vegan |
| `mealType` | string | Any meal, Breakfast, Lunch, Dinner or Evening snack |
| `taste` | string | For example Any, Spicy, Mild, Tangy |

Response:

```json
{
  "meals": [
    {
      "emoji": "🍳",
      "name": "Egg bhurji with rice",
      "description": "Spiced scrambled eggs with onion and tomato.",
      "cost": 45,
      "time": 15,
      "protein": 14,
      "ingredients": ["eggs", "onion", "tomato", "rice", "oil", "salt"],
      "steps": ["Heat oil in a pan.", "Add chopped onion and cook until soft."]
    }
  ]
}
```

A meal may also include a `youtube` object (`url`, `title`, `thumbnail`, `channel`) to show the video card.

Errors:

| Status | Meaning |
| --- | --- |
| 400 | Ingredients missing, or budget or time is not a number |
| 502 | The model did not return valid meals after two attempts |

## How missing ingredients work

For each meal, the client compares every item in `meal.ingredients` with the ingredients the user typed. Names are lowercased, stripped of punctuation and reduced to the singular form, then matched in either direction, so "eggs" matches "egg". When **Pantry basics** is on, items such as salt, oil, turmeric and common masalas count as owned. Anything left over is shown as missing.

Because this is a name comparison, "rice flour" counts as having "rice". If you need stricter matching, have the server return a `missing` array per meal, which the client will use instead.

## Responsive design

The layout changes at three screen sizes, using Tailwind's `md` (768px) and `lg` (1024px) breakpoints.

| Device | Screen width | Layout |
| --- | --- | --- |
| Phone | under 768px | One column. The form dropdowns are 1 column under 400px and 2 columns above that. The shopping list sits under the results. The recipe video card stacks its thumbnail above the text under 480px. |
| Tablet | 768px to 1023px | Still one column, but the form uses the extra width: the ingredient box and the common-items picker sit side by side, and the eight dropdowns form a 4-column grid. Sort and filter sit beside the results heading, and an opened recipe splits into ingredients and method columns. The shopping list stays under the results. |
| Desktop | 1024px and up | Two columns: a sticky 360px sidebar with the form and shopping list, and the meal results on the right. |

Other small-screen details:

- Below 1024px, tapping **Find meals** scrolls down to the results, and scrolls back up to the form if the request fails.
- Inputs use 16px text on phones so iOS Safari does not zoom the page when a field is focused.
- Buttons and chips have larger tap areas on small screens.
- Long ingredient and meal names wrap instead of pushing the page sideways.

Tablets sit on both sides of a breakpoint depending on size and rotation. An iPad in landscape (1024px or wider) gets the desktop layout. A small tablet in portrait, such as an iPad mini at 744px, gets the phone layout.

## Troubleshooting

- **"Could not reach the meal service":** the server is not running, or `API_URL` points at the wrong address or port.
- **401 or 403 from Hugging Face:** the token is missing or wrong, it lacks Inference Providers permission, or the model license has not been accepted. Check `HF_TOKEN` in `server/.env`.
- **502 "Could not generate valid meals":** the model returned broken JSON, or every meal went over the budget or time limit. Try again, raise the budget or time, or move to a larger model.
- **Meals feel slow:** small hosted models can take several seconds. The skeleton cards show while it works.
- **CORS error in the browser:** make sure `app.use(cors())` is in `server.js` and the server was restarted.

## Notes on the AI

- The model runs on Hugging Face, so no model weights are downloaded locally.
- Small models can ignore rules, so the server checks every meal before sending it on.
- Costs and protein values are estimates from the model, not nutrition facts.

## Security

- Keep `server/.env` out of version control. Make sure both `.env` files and `node_modules/` are listed in a `.gitignore`.
- The Hugging Face token must stay on the server. Do not put it in the client code.
